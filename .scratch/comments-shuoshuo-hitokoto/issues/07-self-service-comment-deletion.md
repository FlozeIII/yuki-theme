# 07: 访客删除自己的评论

**What to build:** 访客提交评论后收到一封带链接的邮件。打开链接看到一个确认页，确认之后那条评论被删掉。链接一次性、会过期、只对那一条评论有效，全程不需要注册账号。

打开链接先到确认页而不是直接删除，这一条是必要的：邮件客户端和聊天软件会预取链接，直接删除会在用户还没看到邮件时就把评论删掉。

**Blocked by:** 01

**Status:** ready-for-agent

- [x] 评论提交成功后发出通知邮件，正文里含一条删除链接
- [x] 打开链接看到确认页，而不是直接执行删除
- [x] 确认之后评论被移除，站点上不再可见
- [x] 同一条链接第二次使用无效
- [x] 过期的链接无效
- [x] 一条评论的删除链接不能用来删除另一条评论
- [x] 不带有效令牌的请求无法通过这个路径删除评论
- [x] 仅预取链接（不点确认）不会导致评论被删
- [x] 全程不要求注册或登录
- [x] 删除后不留可见的空壳

## Comments

验证方式：`node tests/bin/verify-comment-deletion.mjs` —— **38/38 通过**（落在提交 `37f69b7`）。

实现落在 `inc/comment-deletion.php`（函数体）加 `functions.php` 末尾一行显式 `require_once`。

### 实现要点

- **令牌存在那条评论自己的元数据上**（存摘要不存原文，HMAC 用站点 salt 签名）。
  「令牌与评论一一绑定」是这么来的：拿甲的令牌配乙的 id，摘要对不上。
- **一次性**靠删除本身——`wp_delete_comment( $id, true )` 彻底删掉，链接自然失效。
- **确认走 POST**，且 POST 与 GET 的令牌分开读（不给「拿 GET 的令牌满足 POST」留口子）。
  正因为确认是 POST，邮件客户端的预取（一个 GET）只会看到确认页，删不掉东西。
- **不管审批状态都发信**：评论还在等他审核，他也该能自己撤回去。挂在 `comment_post` 上，
  所以被防垃圾挡下的提交不会白发一封邮件。
- 页面状态码一律 200：这是给访客看的页面，不是在报错。

### 子评论不会跟着消失

`wp_delete_comment` 会把子评论**上提一级**而不是连带删除（`wp-includes/comment.php:1589-1593`）。
所以访客删自己那条评论，别人对他的回复会留下、父指针也不会指向空评论——
「删除后不留可见的空壳」这条不需要额外做什么。

### 变异验证

| 变异 | 结果 |
| --- | --- |
| 打开链接即删除（`if ( true )` 取代确认判断） | 「只打开链接（预取）不会删掉评论」变红 |
| 忽略过期时间 | 三条过期断言变红 |
| 不比对摘要（任何令牌都放行） | 跨评论、伪造令牌的断言变红 |
| 摘要改存**站点级** option（任何一发有效令牌都能删任何一条） | 「拿丁的有效令牌打乙」变红 |

最后一条是代码审查揪出来的：跨评论那节原本用的是**甲那条已经被删掉的**令牌，
于是失败原因是「评论不存在」，「令牌与评论一一绑定」这条根本没被验到——
把摘要存成站点级、任何一发有效令牌都能删任何一条，原来的用例照样全绿。
现在专门多发一条评论提供一枚**仍然有效**的令牌来打另一条。

**一处验不到的边界，写下来免得被误以为覆盖了**：「链接一次性」只验得到「第二次使用无效」，
**验不出**「令牌是用过才失效的」——成功删除会把评论一起删掉，第二次失败在「评论不存在」
那一关，两件事在这个实现里是同一次观察。这个实现里不存在「评论还在、令牌已作废」的状态
（`perform` 先撤令牌再删评论，删除失败也不会留下可用的链接），所以没有硬造。

### 测试自身的三处毛病（都是红的时候露出来的）

1. **动手前就抓到的假绿**：所有「链接无效」的断言原本写成「页面上**没有**『确认删除』字样」，
   这在页面**压根没渲染**时也成立——第一版红的时候，5 条「无效」断言其实是「页面是空的」。
   改成只认**正向标记**（`yuki-delete-confirm` / `-invalid` / `-done`），页面没出来就落到 `other`。
2. **`is_email()` 拒掉非 ASCII 的本地部分**：测试原本用 `yuki-del-甲-<ts>@example.test` 当邮箱，
   于是主题**正确地**拒绝发信，而我读成了「邮件没发出来」。是测试错了。
3. **各节共用一个基线却各自为政**：伪造令牌那一节的断言会在「评论已经被上一节删掉」时
   静默通过（令牌再烂也过不了「评论还在吗」那一关）。每节现在先断言自己的基线还在。
