# 02: 评论防垃圾

**What to build:** 访客正常填表提交的评论，行为与改动前完全一致。而填了那个看不见的字段、或者页面刚加载就瞬间提交的提交，会被当作垃圾挡在**入库之前**——站点上不出现它，待审队列里也没有它。

蜜罐字段的设计要点：它必须是正常访客不会碰、密码管理器也不会自动填充的那种。时间戳令牌必须带本站签名，否则被随意填一个值就能绕过。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 评论表单里存在蜜罐字段，但它不出现在任何面向访客的输出中（评论列表、feed 里都没有）
- [x] 蜜罐字段被填充时，提交不产生任何评论
- [x] 页面渲染到提交之间短于 3 秒时，提交不产生任何评论
- [x] 时间戳令牌带本站签名；被篡改或凭空伪造的值会被判为无效
- [x] 被挡下的提交不进入待审队列
- [x] 正常填写的提交，结果与改动前一致（该待审的待审，该发布的发布）
- [x] 用密码管理器自动填充整个表单后提交，不会被误判

## Comments

实现：提交 `b1bbb43`。验证方式：`node tests/bin/verify-comment-spam.mjs` —— **34/34 通过**
（这一版）。造数脚本 `tests/bin/comment-spam-fixtures.php`，断言只走 HTTP。

判定链：表单侧在 `comment_form` 上挂蜜罐与令牌；拦截侧挂 `pre_comment_approved`，返回
**不带 data** 的 `WP_Error`。核心在 `wp_check_comment_data()` 里就此短路，`wp_new_comment()`
直接把它返回，`wp_insert_comment()` 不执行；`wp-comments-post.php` 对没有 data 的 WP_Error
走 `exit;` 分支，既不入库也不回任何内容（垃圾提交者拿不到「被识破」这个信号）。「入库之前」
是核心文档写明的行为，不是撞运气。

七条各自落在哪里：

1. 表单里只有那一个访客看不见的 input（`aria-hidden` 容器、`tabindex="-1"`、整块移出可视
   区域的 CSS），全页只有表单内这一处；评论 feed 里没有它。
2. 填了蜜罐 → 提交被挡，标记文本在文章页、feed 与三个后台队列里都搜不到。
3. 同一个令牌：趁它没过 3 秒先提交一次 → 被挡；等过窗口再提交 → 正常发布。把窗口改成 0
   再跑，这一条会红。
4. 签名校验单独验：把令牌的提交时刻换掉、签名原样留着（换过的时刻仍是「够老」的），
   此时只有签名校验拦得住；另加「凭空伪造」「整条不给」两条。
5. 被挡下的提交在 `comment_status=moderated`、`spam`、`all` 三个后台列表里都不出现
   （登录态也是走 HTTP 拿的）。
6. 老读者邮箱（有过通过的评论）→ 302 到 `#comment-N`，评论当场出现在文章页与 feed；
   新访客 → 302 带 `unapproved=`，只进待审队列、访客看不到。
7. 这条只验到能做到的限度：**自动填充没法脚本化驱动**，所以验的是字段契约（名字不含
   自动填充词汇、`autocomplete="off"`、不是 email/url/tel 这类、不可键盘到达、非必填、
   无 placeholder）加上行为（姓名/邮箱/网址/正文都填满的正常提交照旧发布）。另用无头 Edge
   截图看过一次渲染结果，表单里只有正常的四个字段。

**刻意的取舍**，都写在 `functions.php` 的注释里：

- 令牌只设 3 秒下限、不设上界。开着页面缓存时令牌会偏老，加上界会把缓存命中的访客一并拦掉；
  代价是同一个令牌可以反复用。它挡的是「随手填一个值」和「页面刚出来就提交」，一个肯自己
  取页面、肯等三秒的脚本本来就挡不住，那种交给审核队列与黑名单。
- 只判定「访客在评论表单里交上来的」那一种。REST、XML-RPC、定时任务、命令行调用手上不该有
  令牌，判它们为机器人只会静默吞掉别处正常入库的评论；这些路径上核心自己的审核、黑名单与
  频率限制照旧生效。
- 判定按**服务端渲染时刻**算（工单的措辞就是「页面渲染到提交」）。开着页面缓存时它与访客
  真正打开页面的时刻会差一截，宁可放过也不会误伤。

**前提**：本地跑这套断言前先装基建（`node tests/bin/harness.mjs install`）。工单 01 的
`yuki-dev-comment-flood.php` 关掉了内核的评论频率限制（15 秒窗口）——不关的话，这套用例
自己连着发的提交会先被 429 拦掉，「瞬间提交」那条会**假通过**。断言认这个信号：被挡下的
提交若回 429，直接判失败并提示先装基建。
