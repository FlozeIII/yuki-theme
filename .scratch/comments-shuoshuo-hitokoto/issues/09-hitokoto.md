# 09: 一言

**What to build:** 侧边栏露出一句随机的话。内容由**服务端**取回并缓存一小时，访客的浏览器不直接请求第三方，因此访客的 IP 不会交给它，第三方也不会被高频敲打。上游超时、报错或返回无法解析的内容时，页面上出现主题内置的一句兜底——页面不会缺一块，也不会被拖慢。

一言是本主题唯一的**不自足功能**（见 `CONTEXT.md`），兜底是它的必要条件而不是加分项。

放置方式：作为侧边栏的内置默认小工具之一。侧边栏已经有「放了自定义小工具就接管、一个都不放则回退内置默认」的机制，放进去就天然可关闭。

**Blocked by:** 01

**Status:** ready-for-agent

## Comments

实现：`ea34434`。验证方式：`node tests/bin/verify-hitokoto.mjs` —— **46/46 通过**。

### 形状

`yuki_hitokoto()` 返回 `array( 'text', 'source' )`，取回、兜底、清洁各一个函数，挂在
`functions.php` 里与其它功能并列；显示在 `sidebar.php` 的**内置默认小工具**里（作者简介之后）。
放在 else 分支里就天然可关闭——「放了自定义小工具就接管」是既有机制，一言没有为「关掉我」
长出一个开关。

上游是 `https://v1.hitokoto.cn/?encode=json&charset=utf-8`（**宿主在境内**，与头像镜像同一条约束）。
出处跟着句子一起显示（一言的惯例），有就显示、没有就只显示句子。

### 三处不显然的取舍

1. **失败的那一份也要缓存**（5 分钟，成功是一小时）。不缓存的话，上游挂着时**每个访客每次
   打开页面**都要等一遍超时——「上游挂了页面也没明显变慢」就成了空话。冷却期比一小时短得多，
   为的是上游恢复之后站点能自己回来，而不是把故障记满一小时。
2. **超时 2 秒**，不是 WordPress 默认的 5 秒。这一段在页面渲染路径上。验收里有一条就是照着
   这个定的：上游挂住时首次渲染必须 < 3.2 秒（实测 2.4 秒）；把这个值改回 5，它会红。
3. **入口处不剥标签，转义留给输出那一端**（`esc_html`）。两边都做的话，「输出前转义」这条
   验收就再没有东西可验了。代价是缓存里存着上游的原文——它只经由 `esc_html` 出去。

### 变异验证

| 变异 | 结果 |
| --- | --- |
| 输出处去掉 `esc_html` | 「上游给的标记不会被当成 HTML」「输出里是转义后的形式」变红 |
| 不显示出处（`cite` 整块不输出） | 「出处跟着一起显示了」「转义后的出处确实显示了出来」变红 |
| 缓存改成 60 秒 | 「缓存的有效期是一小时」变红（59 秒） |
| 失败不写缓存 | 「上游挂着时后续访问不再等它」变红（10.8 秒）、「不再敲它」变红（又命中 2 次） |
| 超时改成 5 秒 | 「取回超时不会把页面拖到 WordPress 默认的 5 秒」变红（5.5 秒） |
| 内置默认无视 `is_active_sidebar()` | 「接管之后一言不再出现」变红 |

值得记一句：把缓存 TTL 改成 60 秒时，「一小时之后会重新取回」**没有**红——它验的是
「到期会重新取回」，TTL 有多长由「缓存的有效期是一小时」那条单独验。两条合起来才是勾选项
的第三、四条；单独看任何一条都会以为覆盖到了。

### 代码审查改掉的四处（都不是功能问题，是**验得不够**）

1. **勾选项「上游不可达时页面渲染没有明显变慢」原本落在隔壁**。那条断言（耗时 < 上限）我一开始
   只写在「上游挂住」那一节；不可达那一节算了耗时却不断言。字面上对的、实质上空了。现在两处
   都断言，并写清楚各自在防什么：连接被拒是立刻返回的，那条只是不让失败路径离谱；**只有超时
   能真的拖慢页面**，那一条在 `hang` 那一节。
2. **「转义」原本只有反向断言**（未转义的标记不出现）。出处整个不输出时它照样绿，等于没验。
   补了一条正向的：转义之后的那一份确实显示了出来（变异验证：`cite` 不输出即变红）。
3. **「页面没有缺一块」原本只查 `</html>` 在不在**，近乎恒真。改成查侧边栏本身还在、而且另外
   四个内置小工具（作者简介/分类/标签云/热门文章）都在——一言取不回来时，周围那几块不该跟着消失。
4. **一条恒真的断言删掉了**：「显示的那句在池子里」——取句子的辅助函数本来就只在池子里找。

### 记录两处**超出勾选项**的东西（是选择，不是遗漏）

- **显示出处**。spec 只要求「露出一句随机的话」，出处是我加的。理由：一言的惯例是带出处，
  它是「取自外部服务」这句话的一部分，也为氛围服务（极简线之内）。介意的话删掉
  `source` 那一支即可，兜底句的 source 本来就是空的，显示逻辑天然退化成「只有句子」。
- **失败时也缓存兜底句（5 分钟）**。spec 只说要一小时的缓存。这是「上游挂了页面也不能变慢」
  那条的实现手段：不缓存的话，上游一挂，**每个访客每次打开页面**都要等一遍超时。

### 已知的边界

- **耗时阈值是照着本机实测定的**（空转 ~0.4 秒，超时路径 ~2.4 秒，上限取 3.2 秒）。换一台机器
  应当重测基线再改这两个数；它要抓的是「用了 5 秒默认超时」这种量级的差别，不是几十毫秒的抖动。
- **夹具之间重复了一份引导脚手架**（`*_fixtures.php` 的头部、`tryFx`）。这是仓库现有的形状，
  每个工单的造数脚本都能从头读到尾；抽公共层要动别的工单的文件，不在这一单里做。

### 上游故障怎么造

- **500 / 垃圾正文**：stub 的 `mode` 写成 `500` / `garbage`。
- **不可达**：把 stub 进程杀掉（端口不再监听，连接被拒）。
- **超时**：stub 新增了 `hang` 模式——**接住请求但永不回应**。这是本地唯一能造出超时的办法：
  杀进程得到的是「连接被拒」，那是另一种失败，快得很，验不出「超时不能拖慢页面」。
  它扩展的是工单 01 的基建（已在 `tests/README.md` 记上），且**用完立刻还原成 `ok`**——
  `mode` 是全局状态，`hang` 会让**任何**敲这个 stub 的请求挂住，包括别的会话的验收。
  收尾覆盖到 SIGINT/SIGTERM（`finally` 在 Ctrl-C 下不跑）。

### 一条只有真浏览器能验的事

「访客的浏览器不直接请求第三方」拆成两半：HTML 里**不出现上游的地址**，以及用无头 Edge
加载页面后 `performance.getEntriesByType('resource')` 里**没有发往上游的请求**。
后者是这条勾选项的实质——`pre_http_request` 只挡得住 PHP 发出去的请求，主题把地址写进页面、
浏览器自己去取这种事它看不见。

（顺带踩了一次：这条断言一开始按「页面里不出现 `hitokoto` 这个词」写，而主题自己的类名
`yuki-hitokoto` 就带这个词，于是它红在一个跟上游毫无关系的地方。改成认主机名 `hitokoto.cn`。）

### 两处共享环境的竞争，以及它们的处理

1. **主题被切走**：工单 01 的验收会真把主题切成 `twentytwentyfive`，那几秒里一言一个断言都
   验不了。脚本开头会**等主题切回 yuki**（最多 12 秒）再开跑，而不是把这段竞争记成失败。
2. **`mode` 全局**：见上，用完立刻还原。

另外这次改动也顺手补了两处「对外发布」该有的东西：README 的「无第三方依赖」不再成立
（一言是唯一的外部依赖，已改写并把降级写进去），侧边栏的注册描述里补上了「一言」。
