# 04: 说说的承载体配置与主列表排除

**What to build:** 站点所有者可以在自定义器里指定哪个分类承载**说说**。被指定分类里的文章不出现在首页与博客归档，但那个分类自己的归档页照常列出它们。分类不存在、被删或未配置时，功能安静地不生效——不留空白、不报错。

配置必须存**分类标识**而不是 slug，否则用户改名或换 slug 就失效（见 ADR 0001 的影响一节）。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 自定义器里可以选一个分类作为说说的承载体
- [x] 承载体分类里的文章不出现在首页列表
- [x] 承载体分类里的文章不出现在博客归档（含分页的后续页）
- [x] 承载体分类自己的归档页正常列出这些文章
- [x] 未配置承载体时，一切行为与改动前一致，页面既不空白也不报错
- [x] 承载体分类被删除后，站点不报错、不空白，行为退回「未配置」
- [x] 承载体分类改名或更换 slug 后，配置仍然有效
- [x] 主题激活时，若默认承载体分类不存在则创建它
- [x] 其他分类、标签、日期归档的列表不受影响

## Comments

验证方式：`node tests/bin/verify-shuoshuo.mjs` —— **49/49 通过**（主题侧落在提交 `46b1f05`）。

### 实现要点

- 配置存 **term_id**。自定义器那个下拉的值就是 term_id（选项里 0 表示「不使用」），
  所以站主改名、换 slug 都动不了它。
- 排除加在**主查询的 `is_home()`** 上，用负的 `cat` 参数而不是事后过滤结果——
  这样分页与总数才是对的（第一页补满、总页数少一页），翻页不会读到一页空白。
- 「分类被删」与「从来没配过」走同一条路（`category_id()` 返回 0），
  调用方只判断 0，页面既不报错也不留空白。
- 主题启用时若没有可用配置，按默认 slug `shuoshuo` 建一个并写配置。硬编码的只有这个
  slug，且**只在没有可用配置时用一次**，此后一切以配置为准。

### 一个真实的缺口：置顶文章绕得过排除

负的 `cat` 参数靠 `category__not_in`，而 WP_Query 处理置顶文章时**只认 `post__not_in`**
（`class-wp-query.php:3604`）；剩下没被排除掉的置顶文章会被
`get_posts( array( 'post__in' => $sticky_posts ) )` **重新查一遍**（那里一个分类条件都没有）
再插到列表最前面。结果是一篇被置顶的说说照样出现在首页顶上。

代码审查抓到这条，已用 `the_posts` 在结果出来之后兜一道。兜底**不会**在页面上留空位：
那篇文章本来就被主查询排除了，是置顶逻辑把它加回来，去掉只是把条数恢复成应有的样子。

### 变异验证

断言不是「跑绿就算」：

| 变异 | 结果 |
| --- | --- |
| 摘掉 `pre_get_posts` 里的排除 | 4 条排除断言变红 |
| 配置改成按 slug 存、按 slug 取 | 9 条变红，含整个「改名换 slug」小节 |
| 摘掉 `the_posts` 置顶兜底 | 「置顶的说说也不出现在主列表」变红——正是它要防的缺口 |

### 两个踩到的坑，写下来免得下次重踩

1. **`after_switch_theme` 不在 `switch_theme()` 里触发。** `switch_theme()` 只把切换记进
   `theme_switched` 选项（`theme.php:840`），真正 `do_action` 的是**下一次页面加载**时的
   `check_theme_switched()`（挂在 `init` 上，`default-filters.php:372`）。验收脚本因此走
   「登记切换 → 真发一次 HTTP 请求 → 再读状态」这条真实路径。
2. **夹具不能替主题假定配置怎么存。** 造数脚本一开始直接把 theme mod 当整数解，
   于是主题真按 slug 存时夹具连分类都找不到、测试在门口就崩，改名那条断言根本没机会跑。
   现在夹具问主题 `yuki_shuoshuo_category_id()`「说说归哪个分类」，也不覆盖已有的可用配置。

另外两处测试自身的修正：说说原本是**先**发的，于是 12 篇正式文章占满第一页，
「首页不含说说」在排除逻辑完全没写时也是绿的（假绿）；造数条数改成按站点
`posts_per_page` 计算，而不是写死 12——写死的话每页条数一旦被调大，第二页就可能是空的。
