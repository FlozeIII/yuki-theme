# 03: 被挡下时说得清：两种判定拆开

**What to build:** 防垃圾守卫今天对两种判定**共用一个出口**，而且那个出口是一片空白。可这两者挡的根本不是同一种东西：

- **填了那个隐藏字段** —— 确定性的机器人信号。静默丢弃，什么也不告诉它。
- **提交太快** —— 只是个怀疑，而付代价的可能是手快的真人（粘贴好一段话、两秒内点了提交）。他今天看到的是白屏，评论静静地没了。

所以拆开：前一种照旧静默；后一种给一句能照做的话——**再点一次就成功了**，因为那三秒窗口早过了。

**没脚本的那条路要同步改。** 它今天对两种判定都给一片空白页。两条路说法不一致，比两条路都差还难查。

判定仍然发生在评论**入库之前**，垃圾不落库、也不进入待审队列——这一条不动。

## Comments

### 判定怎么拆的

守卫原来对三种情况共用一个出口（不带 data 的 `WP_Error`，两条路都是一片空白）。现在按
「这是不是一笔本表单交上来的提交」分成两类：

| 判定 | 依据 | 出口 |
|---|---|---|
| 填了蜜罐 | 隐藏字段非空 | **静默**：错误里不带话也不带 data → 原生入口 `exit;`、端点回空话 |
| 令牌不是本站签的 / 没带 | 格式不对、签名对不上 | 同上（与蜜罐同一类：确定性的信号） |
| **令牌是真的，只是太快** | 签名对得上，但页面渲染不到 3 秒 | **给一句话**，带状态码 429 |

签名对得上才是关键分界：它证明这一笔确实出自本站渲染的表单。签不出以假乱真的令牌，所以
「签名不对」只能是手编或伪装；而「签名对、时间短」只说明**这个人手快**。

原生那条路是靠**第三个参数传整数状态码**改过来的：`wp-comments-post.php` 读的是
`(int) $comment->get_error_data()`，拿到非空就走 `wp_die`，把话显示出来（还带一个返回链接）；
给数组会被它用成 1。核心自己那几条也是这么传的（`new WP_Error( 'comment_flood', …, 429 )`、`new WP_Error( 'comment_closed', …, 403 )`）。状态码用 **429** 而不是 403：403 是「不许」，这里只是「太快」，核心自己的频率判定（`comment_flood`）用的也是 429。

**端点与脚本一行没改**：端点的错误映射早就是「核心给了状态码就用它自己的、话剥掉标签带出来」，
脚本早就是「服务端说了话就放到页面上」。这一件只是让守卫第一次说出话来。

### 那句话

> 提交得有点快，这条没能收下——再点一次提交就好。

说得清「怎么办」，但**不说判定窗口有多长**——告诉人「等三秒」等于把规则抄给写脚本的人看。
验收里有一条专门盯着它：那句话里不许出现「秒」「计时」「间隔」这类字眼。

`.yuki-comment-error` 原来是裸的一个 `<p>`（上一件记过这个缺口）。现在它成了这一件的主角，
给它加了与待审提示同款的框，左边竖线用 `--yuki-ink-3`（不是主色）以示区别——设计系统里没有
「危险色」，新添一枚是 `DESIGN.md` 的事，不塞进这一件。

`node tests/bin/verify-comment-submit.mjs`：**173/173 通过**。

红绿记录：先写断言、守卫还没拆时 168/171（HTTP 那几条红的正是「太快没有话」）；拆完守卫后

浏览器这边 `goto` 要等远端的头像图，等回来时页面上那枚令牌早过了三秒窗口，于是**测不出「太快」**。

覆盖（这一件新加的）：

- 端点上太快 → 有一句话、那句话让人再点一次、不透露窗口；蜜罐与缺令牌 → **没有话**；
  两者「看到的东西不一样」。
- 无脚本那条路：太快 → **429 + 一张带话的页面**（不是空白）；蜜罐 → 仍然是一片空白。
  （上一件刻意没钉住「空白」这件事，就是留给这一件改的；现在两侧都钉住了。）
- 真浏览器：太快 → 那句话出现了、那条没进列表、**写的内容还留着**、页面没重载；
  然后**真的再点一次** → 成功、没有重载、**那句话自己收掉了**。
- 被挡下的三类（蜜罐/太快/缺令牌）一条都没入库，也没进待审队列（`by-email` 数到 0）。

既有九份回归串行跑过：**388/388**。

### 一件该纠正的事：`.pot` 的生成器一直是有的

前两件我都写了「产出这份文件的生成器这台机器上没装，所以只手工补了 `#:` 出处」。**那是错的。**
生成器在 `C:\Users\Floze\wp-dev\scripts\make-pot.mjs`（`node make-pot.mjs <主题目录>`），它产出的
形状与仓库里那份逐字节对得上。我当时只在仓库里 grep，没去自己的环境笔记里看——而那条笔记里写着它。

这一件按规矩重建了：`git archive HEAD` 到临时目录、把自己改的文件拷进去、再跑生成器。顺带：

- 它把 `single.php`、`inc/comment-deletion.php`、`inc/comment-likes.php` 那十几条**早就指歪的出处**
  一并修正了（那是别处改版留下的；手工补的话不属这一件，生成物本来就该是生成出来的样子）。
- 生成器自己有个 bug：找「紧邻的 `/* translators:` 注释」时，它从窗口里**第一个** `/*` 起算，
  于是只要三十行上面还有一条 translators 注释，就会把中间整段代码吞进注释里——仓库里原本就
  已经有一处被吞成一行了（`你在《%s》下留了一条评论：` 那条）。改成从**最近**的那个 `/*` 起算，
  一处一行，都在 `wp-dev/scripts/make-pot.mjs` 里。那个文件不在版本库里，所以在这儿记一笔。

生成出来的 pot 用脚本逐条核过：能机械核对的 83 条单行 msgid，`#:` 出处对不上的 0 条；也没有被生成器吞成一行的注释。

### 2026-10-17 发布后补丁：令牌加上界、兜底分支要求 comment_post_ID

**令牌加上界。** 原实现的注释写着「只设下限不设上界」，理由是页面缓存可能让 token 比访客打开
页面的时间更早。代价是抓到一个令牌就能**永久**重放。补丁改为：

- `$age < 0`（时间戳在未来/时钟回拨）或 `$age > WEEK_IN_SECONDS` → `missing`（与签名不对同类，
  静默丢弃）；
- `3s ≤ $age ≤ 1 周` → `ok`；
- `$age < 3s` → `too_fast`。

一周对现实的缓存 TTL 绰绰有余，又让被抓走的令牌会自己过期。单独探针实核：
`fresh_after_4s=ok`、`just_now=too_fast`、`old_week=missing`、`future=missing`。

**兜底分支要求 `comment_post_ID`。** `yuki_comment_is_form_post()` 在「POST + 没有亮明端点身份」
的兜底分支上再要求这个字段。别的插件在 POST 里直接调 `wp_new_comment()` 时通常没有它，原实现会
把那类调用当成「没带蜜罐与令牌」的机器人静默吞掉。端点那条路在前面就短路返回，不受影响。

**验收与已知不稳。** `verify-comment-spam` 34/34；`verify-comment-submit` 的 HTTP 断言通过，
但浏览器「太快 → 等 3.4 秒 → 再提交」这一段连续两次红，且失败点相反（一次是错误框没被收掉，
一次是第二次提交没插进评论）。补丁改动的路径不在那段场景的决定性位置上，独立探针也排除了令牌
判定；记录为**共享环境下的已知不稳定场景**，没有据此宣称全绿。测试里那句「令牌只设下限、
不设上界」的过时注释已改直。

**2026-10-17 复跑：** 先修了测试自己的缺口——`guard-scope --context=form` 探针没有塞
`comment_post_ID`，而真实表单一定带它，补丁的兜底判定要求的正是这个字段。补上后
