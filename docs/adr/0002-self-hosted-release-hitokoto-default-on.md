# 发布走自托管，一言保持默认开启

**Status**: accepted

## 决定

本主题的**对外发布**走**自托管分发**（GitHub release、主题包直接交付），不提交 WordPress.org 官方主题目录。

代价是明确的：官方 Required 指南不允许主题在未经用户明示同意时向远程资源取数据，而**一言**恰恰是在侧边栏回退到内置默认小工具时、由服务端在页面渲染路径上请求 `v1.hitokoto.cn`，且刻意不作开关。也就是说，**一言的默认形态与官方目录互相排斥**——我们选择保一言。

## 理由

一言是**不自足功能**，它存在的意义就是让站点露出一句随访问而变化的话。spec 把它放在侧边栏的内置默认小工具里（放了自定义小工具就接管、一个都不放才回退），于是它天然可关而无需额外的开关——这与**对外发布**里「不要求使用者做额外配置」是同一条线。

改成一言默认关闭，等于要求每个使用者先去自定义器里找一下、打开它，才得到主题本来就想给的氛围：把一个开箱即得的东西变成一道配置题。**目录曝光的价值不足以换这个。**

## 被否掉的方案

- **提交官方目录，把一言与头像镜像改成默认关闭 + readme 披露** —— 这才是官方要求的形态。Required §9 原文：「No remote resources are allowed without user consent … Do not fetch any files or data from a remote resource, including your websites, without the user's explicit consent.」技术上完全可行，代价是让出「开箱默认体验」。留作将来可选项，但**要动它得先推翻本条**。
- **提交官方目录，删掉一言** —— 为了合规直接砍掉一个功能，比改默认值损失更大，也与 spec 的取舍相悖。
- **两套发布形态并行**（自托管保默认、目录版另发一份）—— 同一个主题维护两份行为差异，正是最容易被漏掉的那类分叉，不做。

## 影响

- 不写 `readme.txt`，不按官方 Required 清单（前缀、钩子、必备 CSS 类等）全量过审。
- **Theme Check 仍然照跑。** 它是找真 bug 的扫帚，不是合规仪式。
- 自托管仍受 Required §14 约束：只能分发 100% GPL 兼容的主题，且分发页面要在显眼处声明。LICENSE 已是 GPL-2.0，达标。
- 将来有人翻到 `CONTEXT.md` 的**对外发布**、再看一眼 `v1.hitokoto.cn` 那条请求，会先问「为什么不干脆提交官方目录」。答案在本条。**别把「一言默认外呼」当成疏漏顺手修掉**——它是刻意选的。
